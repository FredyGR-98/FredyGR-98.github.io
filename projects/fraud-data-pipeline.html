Pipeline de scoring para monitoreo transaccional

Flujo de datos con API, validación, modelo y dashboard conectado, usando una composición técnica más esquemática.

Problema de negocio

Un modelo aislado tiene poco valor si no puede integrarse de forma reproducible con la operación. Este caso se enfoca en convertir la lógica analítica en una capa usable por APIs, dashboards y futuras integraciones.

Qué se analizó

Se revisó qué variables podían sostenerse en tiempo real, cuáles debían excluirse por riesgo operativo y cómo preservar esa decisión en metadata reutilizable.

Solución implementada

Se empaquetó un pipeline de inferencia con metadata, features esperadas, umbral de decisión y endpoints para salud, scoring e integración.

Resultados obtenidos

El sistema quedó preparado para ejecutarse localmente o en Docker con API y dashboard desacoplados, validación de entradas y una ruta clara hacia consumo analítico.

Qué problema resuelve

Muchas soluciones analíticas se quedan en notebooks o scripts de prueba. Aquí el objetivo fue dejar una capa técnica que permita usar el modelo de forma consistente, validada y entendible para otros componentes.

Por qué importa

Cuando una solución puede recibir inputs estructurados, devolver scoring reproducible y alimentar un dashboard, deja de ser una demo aislada y se acerca a una arquitectura aplicable.

Qué se analizó

La selección final de variables se hizo con criterio operativo. Se documentaron features viables en tiempo real y se excluyeron señales que dependen de información posterior a la transacción.

  • Features finales exportadas a JSON para alinear inferencia y validación.
  • Metadata del modelo con threshold y notas de uso operativo.
  • Separación explícita entre señales utilizables y señales descartadas.

Decisiones de ingeniería

La documentación de artefactos evita que la API dependa de supuestos ocultos. Esto facilita mantenimiento, pruebas y extensibilidad de la solución.

Qué solución se implementó

  • Pipeline serializado para cargar inferencia sin reentrenamiento.
  • Endpoints de salud, información del modelo y scoring.
  • Scoring batch para simular monitoreo por volumen.
  • Salida plana orientada a Power BI para seguimiento externo.
  • Docker Compose para levantar API y dashboard en conjunto.

Qué habilita esta capa

Permite que la lógica del modelo no quede atrapada dentro del notebook y pueda consumirse desde un dashboard, probarse por lotes y reutilizarse en flujos posteriores de automatización.
