Problema de negocio

Aunque es un caso académico, funciona como base para demostrar cómo empaquetar un modelo pequeño en una API clara y fácil de consumir.

Qué se analizó

Se usaron largo y ancho de sépalo y pétalo para clasificar tres especies de flores, aprovechando un dataset clásico y bien estructurado.

Solución implementada

Se entrenó un Random Forest, se expuso vía Flask y se añadió una interfaz HTML con sliders y ejemplos para facilitar la prueba del modelo.

Resultados obtenidos

El proyecto deja una base ordenada para servicios de ML: API, pruebas, interfaz ligera y contenedor listo para ejecución portátil.

Qué problema resuelve

Sirve para demostrar de forma clara cómo una predicción puede consumirse desde navegador o consola, sin depender de una notebook o de pasos manuales poco reproducibles.

Por qué importa

Este tipo de proyecto fundacional es valioso porque establece un patrón reutilizable para casos futuros: entrenar, servir, probar y contenerizar.

Qué se analizó

  • Largo y ancho del sépalo.
  • Largo y ancho del pétalo.
  • Patrones básicos entre Setosa, Versicolor y Virginica.

Lectura analítica

El objetivo no era construir un caso de storytelling de negocio, sino una estructura limpia que muestre el paso desde datos tabulares a un servicio funcional y fácil de explicar.

Qué solución se implementó

  • Entrenamiento del modelo con scikit-learn.
  • API REST en Flask para predicción vía JSON.
  • Interfaz HTML con sliders y ejemplos precargados.
  • Pruebas automáticas para validar la API.
  • Docker para despliegue portable.

Cómo se aplica en negocio

Aunque el dataset es clásico, la estructura del proyecto es la parte más transferible: cualquier clasificador tabular puede beneficiarse de este patrón de exposición y prueba.

Resultados obtenidos

API Flask funcional Interfaz HTML interactiva Pruebas automatizadas Docker listo Predicción por JSON Base reusable para otros modelos
