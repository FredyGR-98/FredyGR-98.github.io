Monitoreo de transacciones y riesgo de fraude

Este caso aborda un problema frecuente en banca y pagos: detectar señales de fraude sin saturar la operación con alertas innecesarias. La solución combina análisis exploratorio, reglas de riesgo, modelo supervisado, API y dashboard para traducir datos transaccionales en decisiones priorizadas.

Centro de monitoreo financiero, scoring de riesgo, alertas y un dashboard ejecutivo con lenguaje visual bancario.

Problema de negocio

En un entorno financiero no basta con detectar fraude; también hay que decidir qué revisar primero y con qué nivel de confianza. El desafío es reducir el ruido de alertas y concentrar la atención en señales de riesgo realmente útiles.

Qué se analizó

Se estudiaron patrones de monto, tipo de transacción, balances y reglas operativas sobre PaySim para identificar combinaciones que reflejan transferencias riesgosas, retiros sospechosos y vaciamiento de cuentas.

Solución implementada

Se construyó una capa analítica y una capa operativa: EDA, reglas de riesgo, modelo supervisado, API FastAPI y dashboard Streamlit para monitoreo y simulación de decisiones.

Resultados obtenidos

El sistema prioriza casos críticos con alta precisión, expone inferencia individual y por lotes, y deja una salida preparada para consumo en Power BI y seguimiento ejecutivo.

Qué problema resuelve

Los fraudes suelen representar una fracción mínima del volumen total de transacciones, por lo que un indicador global como accuracy puede ocultar el verdadero desempeño operativo. El foco de este proyecto es distinto: ayudar a decidir qué revisar, cuándo y por qué.

  • Reduce la carga operativa al priorizar transacciones con mayor riesgo.
  • Evita falsas alertas innecesarias que desgastan al equipo.
  • Conecta el análisis con una lectura entendible para negocio.

Por qué importa

Una solución de fraude útil no solo clasifica, también mejora tiempos de revisión, foco de análisis y sostenibilidad operativa. Ese ángulo es el que vuelve relevante este caso para contextos reales de monitoreo.

Qué se analizó

El análisis exploratorio se usó como base para entender cómo se comporta el fraude antes de entrenar el modelo. Eso permitió seleccionar variables viables en tiempo real y descartar señales que no serían operativamente sostenibles.

  • Monto de la transacción y relación con balances.
  • Tipo de operación y banderas de transferencia.
  • Reglas combinadas para detectar patrones de mayor riesgo.

Lectura analítica

Más que buscar una visualización bonita, el objetivo fue producir señales interpretables para un flujo de revisión. El dashboard se diseñó para comunicar métricas, contexto y simulación operativa en lenguaje claro.

Qué solución se implementó

La solución integra análisis, modelo y capa de consumo para simular un flujo más cercano a una operación real.

  • EDA y reglas de riesgo para entender el fenómeno antes del modelado.
  • Modelo Random Forest balanceado para scoring operativo.
  • API FastAPI con endpoints para salud, información y predicción.
  • Dashboard Streamlit para monitoreo, lectura ejecutiva y simulación.

Cómo se aplica en negocio

El sistema permite que un analista o equipo de monitoreo vea qué casos merecen atención inmediata, revise lotes de transacciones y utilice una salida preparada para análisis complementario en Power BI.

Resultados obtenidos

Según los metadatos del modelo desplegado, la versión operativa alcanzó métricas sólidas para priorización de alertas, manteniendo una lectura alineada con negocio.
